## Why

`docs/index.html` (the published book, ~6,100 lines, single static file) has three concrete, verified defects that hurt readability and navigation: internal links that go nowhere, an orphaned placeholder string repeated throughout the running text, and a heading structure that skips a level. These were found by direct inspection (href/id cross-reference, duplicate-paragraph scan, heading-tag audit), not by inference — see counts below. Output goes to a new `docs/index_v1.html` so the current published `index.html` is untouched until this is reviewed and accepted.

## What Changes

- **Fix broken internal links** — every `href="#pg-N"` link in the table of contents (45 unique targets, 100% of them) points to a `id="pg-N"` anchor that does not exist anywhere in the document; clicking any TOC page-range link does nothing. Separately, 3 cross-reference links (`#2-யாத்ருச்சிகப்படி`, at lines 671, 732, 2585) use the wrong chapter-number prefix — the real heading is `id="12-யாத்ருச்சிகப்படி"` — so they resolve to nothing instead of jumping to chapter 12. One row (line 5877, "47.") was templated as a TOC entry ("18 அயடைய" title, stray "அடைய" wrapped as a fake page-link with `href="#"`) but is actually an errata/corrigenda entry — its neighbors (lines 5878+) are the book's own "பிழை - திருத்தம்" (errors/corrections) list, format `<strong>N.</strong> line original-text — பக்கம் corrected-text`. Re-templated to match: `<p class="toc-entry"><strong>47.</strong> 18 அயடைய — பக்கம் அடைய</p>` — restores the "—" separator the wrong template had eaten, no content invented.
- **"பக்கம் ப்ரமாணம் காண்க" and variants (192 occurrences) — REMOVED, on the user's explicit decision.** I initially flagged this as an orphaned digitization placeholder, then found it confined entirely to one distinctly-titled appendix ("அஷ்டாதச ரஹஸ்ய ப்ரமாணத்திரட்டு") with its own internal pagination and recommended leaving it as likely-legitimate structure. The user reviewed the finding and explicitly overrode the recommendation, confirming removal (pasting several occurrences, including the "பக்கம் ப்ரமாணம் 3 &amp; 4 காண்க" variant). Removed all 192 occurrences (187 exact matches + 5 variants with inserted numbers/letters between "ப்ரமாணம்" and "காண்க"); left the distinct "பக்கம் ப்ரமாணம் Nல் பார்க்கவும்" phrasing (different verb, 1 occurrence) untouched since it wasn't part of what was confirmed. Cleaned up the resulting dangling empty brackets and now-empty paragraphs.
- **Fix heading hierarchy — and restore heading borders/spacing that are currently dead CSS.** Headings jump `<h1 class="book-title">` → `<h3 class="chapter-heading">` (×199) → `<h4 class="section-heading">` (×9), skipping `<h2>` entirely. This isn't just a semantic nicety: the *only* CSS rules for these classes are `h2.chapter-heading{...border-bottom:2px...}` and `h3.section-heading{...}` (tag-qualified selectors) — since the actual tags are h3/h4, **every one of the 199 chapter headings and 9 section headings currently renders with zero of its intended styling** (measured: computed `border-bottom: 0px none`, `margin-top: 0px` on a live chapter heading — confirmed via headless-browser inspection, not just reading the CSS). Re-leveling to `h1 → h2 → h3` fixes the hierarchy **and** makes the intended accent-colored, bordered, properly-spaced chapter titles appear for the first time. As a side effect this also activates the existing (currently dead) print rule `h2.chapter-heading{page-break-before:always}`.
- **Fix Tamil paragraph justification — a real, visually-confirmed spacing defect.** Body paragraphs use `text-align:justify` (with `hyphens:auto`, which is a no-op — no browser ships a Tamil hyphenation dictionary). Screenshotted a real paragraph: justify stretches inter-word gaps unevenly into visible "rivers" of whitespace, because Tamil compound words are long and few words fit per line — a well-known problem with justifying Indic scripts. Switch to `text-align:left` (ragged-right), the standard fix for Tamil web typography, and drop the dead `hyphens:auto`.
- **Fix the name-index appendix's internal spacing and one ditto-mark artifact** — the 116 `<table class="idx-table">` fragments that make up the proper-noun index have: (a) entries where multiple unrelated sub-citations were concatenated into one run-on cell with no line breaks (e.g. the "நஞ்ஜீயர்" entry jams together several page citations like "(245)" back-to-back with no separation); (b) one entry whose content is a bare ditto mark ("165. ,,", a print convention meaning "same name as the row above" that doesn't carry meaning once digitized into a table row) — resolved to "அர்ஜுனன்" (matching row 164).
  - **Correction during implementation**: I initially also flagged 9 places where the same number repeats on consecutive entries (e.g. two entries both "172.") as a numbering bug to fix. On closer inspection this number column is a **page number**, not a sequential item count — this is a name/subject index organized by page, and multiple different names legitimately share one page (confirmed: entries "323./323./324./324./324." are different names, each explicitly citing page 245 elsewhere in their own text). Renumbering them would have destroyed real page-reference data. This is **not** touched.
- **Distinguish Sanskrit citations from Tamil translations in the ப்ரமாணத்திரட்டு appendix** — this appendix (1,153 paragraphs, lines 4526-5873) mixed numbered Sanskrit verse citations, their Tamil bracketed translations, inline page-number markers, and section dividers all as identically-styled plain `<p>` tags with no visual distinction. Classified and restyled mechanically (verified against the 187-occurrence hold — none of those paragraphs were touched): verse lines → italic (`.cite-verse`), bracketed translations → indented with a left border (`.cite-trans`), inline page markers → small badge (`.pg-ref`), section/page dividers → small centered label (`.appendix-marker`). Confirmed by diff: zero wording changed, only markup/styling.
- **Fixed a leaked markdown artifact**: 4 paragraphs literally contained the text "**:::Center**" (a fenced-div directive that never got converted during digitization) as visible text. Removed the artifact and wrapped the paragraph in the book's own existing `.text-center` convention (already used 100+ times elsewhere) so the centering it was clearly meant to apply now actually works.
- **BREAKING**: none — this produces a new file (`docs/index_v1.html`); the live `docs/index.html` is not modified by this change.

## Capabilities

### New Capabilities
- `book-link-integrity`: every internal `href="#..."` in the book resolves to a real, correct `id="..."` anchor (TOC page-ranges, chapter cross-references, index jump-links).
- `book-content-cleanup`: investigation of suspected artifact text before touching anything — the recurring "பக்கம் ப்ரமாணம் காண்க" string (investigated, likely legitimate structure, left untouched), the one mistemplated errata row (fixed), and the 1 unresolved ditto-mark index entry (fixed).
- `book-semantic-formatting`: sequential heading hierarchy (h1→h2→h3) which restores currently-dead chapter/section heading styling; Tamil-appropriate paragraph alignment (drop `justify`/`hyphens:auto`); readable internal spacing for run-on index entries; and a distinct visual treatment for quoted verse/citation text within long commentary paragraphs.

### Modified Capabilities
(none — `docs/index.html`'s existing search/transliteration behavior from the prior change is untouched; output is a separate file)

## Impact

- Affected file: new `docs/index_v1.html` (copy-then-edit of `docs/index.html`; the latter is left as-is).
- No build system, backend, or dependency changes — same static single-file architecture.
- Content-integrity lesson from this change: three separate findings that initially looked like meaningless artifacts (a "corrupted" TOC row, "duplicate" index numbers, and the 187-occurrence placeholder phrase) turned out, on closer reading of surrounding context, to be legitimate structure in two cases and probably-legitimate in the third. None were removed without verification; the 187-occurrence phrase specifically is left as-is pending the user's final call (see design.md Open Questions).
- Optional tooling: Sarvam AI (already integrated with a live key in `docs/index.html`'s search feature) can be used to spot-check flagged text spans for OCR/encoding garbling as part of the content-cleanup review, per user request — see design.md.
